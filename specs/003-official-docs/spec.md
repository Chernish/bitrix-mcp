# Feature Specification: Официальная документация с версиями

**Feature Branch**: `003-official-docs`

**Created**: 2026-08-22

**Status**: Complete

**Input**: User description: «добавить в MCP официальную документацию
https://docs.1c-bitrix.ru/; важно учитывать примечания, с какой версии ядра
доступна функциональность»

## User Scenarios & Testing

### User Story 1 — Найти официальное руководство (Priority: P1)

Агент задаёт русскоязычный вопрос и получает релевантные страницы официальной
документации с заголовком, разделом, URL и коротким фрагментом.

**Independent Test**: запрос «защищенные cookie» находит официальную страницу
`/pages/security/secure-cookies.html`.

### User Story 2 — Увидеть минимальную версию (Priority: P1)

Если статья говорит «с версии», MCP возвращает не голое число, а утверждение,
субъект версии, модуль и ближайший заголовок. Для распознанного модуля версия
сравнивается с локальным снимком.

**Independent Test**: `main 23.300.0` при локальном `main 25.100.300` имеет
`availability=available`, а `main 26.0.0` — `requires_newer_module`.

### User Story 3 — Получить воспроизводимый снимок документации (Priority: P2)

Основной сбор читает Markdown из официального Git-репозитория и фиксирует SHA
коммита. Повторный сбор переиспользует локальный shallow clone и не извлекает
неизменённые страницы. HTTP-обход остаётся явным аварийным режимом.

**Independent Test**: два запуска на одном commit дают сначала 199 обновлений,
затем 199 неизменённых страниц; смена версии экстрактора переизвлекает их один раз.

## Edge Cases

- Версии PHP и BitrixVM не сравниваются с версиями модулей ядра.
- Неуказанный модуль не угадывается: `availability=unknown`.
- Несколько примечаний одной статьи сохраняются отдельно с контекстом.
- Короткие служебные страницы не индексируются как содержательные.
- Недоступность документации не повреждает индекс кода.

## Functional Requirements

- **FR-001**: Основным источником MUST быть официальный репозиторий
  `https://github.com/bitrix-tools/framework-docs`.
- **FR-002**: Все `pages/**/*.md` MUST отображаться в канонические URL
  `https://docs.1c-bitrix.ru/pages/**/*.html`.
- **FR-003**: Система MUST сохранять commit SHA и путь Markdown каждой страницы.
- **FR-004**: Версионное примечание MUST хранить версию и исходное утверждение.
- **FR-005**: Если субъект распознан, MUST храниться его тип и код модуля.
- **FR-006**: Сравнение MUST выполняться только с версией явно указанного модуля.
- **FR-007**: Результат MUST различать `available`,
  `requires_newer_module` и `unknown`.
- **FR-008**: Ближайший заголовок MUST сохранять связь примечания с функцией.
- **FR-009**: Индекс кода MUST оставаться источником правды о существовании API.
- **FR-010**: Ответ MUST укладываться в 2000 символов путём явного усечения
  нижних результатов, а не удаления версии у лучшего результата.
- **FR-011**: Обновление формата извлечения MUST инвалидировать старый кэш без
  изменения схемы БД и без полной переиндексации ядра.
- **FR-012**: Режим `--docs-source=web` MUST оставаться доступным как fallback и
  соблюдать robots.txt, паузу и ETag/SHA-256.
- **FR-013**: Ошибка Git/HTTP MUST откатывать транзакцию документации и не
  повреждать уже построенный индекс кода.

## Success Criteria

- **SC-001**: Git-импорт индексирует все 199 файлов `pages/**/*.md`.
- **SC-002**: Повторный импорт той же ревизии не переизвлекает страницы.
- **SC-003**: Контрольные формулировки для main, ui, PHP и BitrixVM
  классифицируются без подмены субъекта.
- **SC-004**: MCP правильно различает доступную и более новую функцию.
- **SC-005**: Все автоматические тесты, typecheck и статический анализ проходят.

## Scope

В область входит концептуальная документация из `pages/`. Генерированный `/api/`
намеренно не дублируется: существование и сигнатуры API определяются локальным
ядром через `bitrix_search_code`/`bitrix_find_symbol`, что требует Конституция I.
