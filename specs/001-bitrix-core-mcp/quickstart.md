# Quickstart: проверка работоспособности

Сценарии, доказывающие, что фича работает от начала до конца. Не руководство по реализации — детали устройства в [data-model.md](./data-model.md) и [contracts/](./contracts/).

## Предварительные условия

Проверено в целевом окружении на 2026-08-12:

| Требование | Проверка | Ожидаемое |
|---|---|---|
| PHP 8.4+ | `php --version` | `PHP 8.4.4` |
| Composer | `composer --version` | `2.8.6` |
| Node 22+ | `node --version` | `v22.21.1` |
| Ядро доступно | `ls $BITRIX_CORE_ROOT/modules/main/classes/general/version.php` | файл существует |
| FTS5 в PHP | `php -r '(new PDO("sqlite::memory:"))->exec("CREATE VIRTUAL TABLE t USING fts5(a)");'` | без ошибки |

**Критично**: `short_open_tag` в этом окружении по умолчанию выключен. Все запуски индексатора выполняются с `-d short_open_tag=1`. Без этого 41% ядра теряется молча (см. [research.md](./research.md), R-001).

```bash
export BITRIX_CORE_ROOT=/Users/sergejcernomordov/stroka/bp/www/bitrix
export BITRIX_MCP_INDEX=./index.sqlite
```

## Сценарий 1. Защита от тихой потери данных

Проверяется первым, потому что его провал обесценивает все остальные проверки: индекс будет выглядеть исправным и при этом врать.

```bash
php -d short_open_tag=0 bin/index.php build
```

**Ожидается**: отказ с кодом возврата 2 и сообщением о выключенной настройке. Индекс не создан и не изменён.

Успешное построение здесь — провал сценария.

## Сценарий 2. Полная индексация

```bash
php -d short_open_tag=1 bin/index.php build
```

**Ожидается**:

- Код возврата 0.
- `SM_VERSION 25.100.300 от 2025-03-21`.
- 93 модуля, из них без версии — 0.
- 67 836 файлов, около 212 МБ.
- Доля ошибок разбора не выше 1% (SC-009). На измеренной выборке при верной настройке ошибок было 0.
- Время в пределах единиц минут (чистый разбор измерен как ~52 с, см. R-002).

**Проверка версионной разноголосицы** — сердце всей фичи:

```bash
php bin/index.php status --deep --json
```

Версии модулей обязаны отличаться и совпадать с файлами ядра: `crm` = `24.1300.0`, `rest` = `25.100.200`, `bizproc` = `24.900.0`, `ui` = `25.0.0`. Одинаковая версия у всех модулей означает, что карта версий не читается и Принцип II нарушен.

## Сценарий 3. Точный лукап с версией (User Story 1, P1)

Через MCP-клиента или отладочный CLI:

```
bitrix_find_symbol { "name": "IblockTable" }
```

**Ожидается**: найден `\Bitrix\Iblock\IblockTable`, `provenance.module = "iblock"`, `provenance.module_version = "24.300.0"`, указаны файл и строка.

Ответ без версии модуля — дефект, а не косметика.

```
bitrix_check_method { "class": "\\Bitrix\\Iblock\\IblockTable", "method": "getMap" }
```

**Ожидается**: `exists: true`, сигнатура, модуль и версия.

## Сценарий 4. Отказ вместо выдумки (Принцип I)

```
bitrix_check_method { "class": "\\Bitrix\\Crm\\DealTable", "method": "getAllDealsQuickly" }
```

**Ожидается**: `exists: false`. Инструмент не предлагает похожий метод как результат. Если похожие имена возвращаются, они помечены как догадка в отдельном поле.

## Сценарий 5. Псевдонимы классов (R-006)

```
bitrix_find_symbol { "name": "\\Bitrix\\Sale\\OrderTable" }
```

**Ожидается**: класс найден, `canonical_fqn = "\\Bitrix\\Sale\\Internals\\OrderTable"`.

Ответ «не найдено» — регрессия: этой формой имени пользуются повсеместно, а объявления с таким именем в ядре нет.

## Сценарий 6. Короткие теги (регрессия R-001)

```
bitrix_find_symbol { "name": "CEventMessage" }
```

**Ожидается**: класс найден. Классы из файлов с коротким открывающим тегом обязаны присутствовать в индексе.

## Сценарий 7. ORM-схема с честной неполнотой (User Story 2)

```
bitrix_get_orm_entity { "entity": "\\Bitrix\\Iblock\\IblockTable" }
```

**Ожидается**: имя таблицы, поля `ID` (`integer`, primary, autocomplete), `IBLOCK_TYPE_ID` (`string`, required), `TIMESTAMP_X` (`datetime`).

У `TIMESTAMP_X` значение по умолчанию задано замыканием, поэтому `default_resolved: false`, а сущность — `is_complete: false` с указанной причиной. Схема, отданная как полная, — нарушение Принципа III.

Проверить и вторую форму объявления — сущность из модуля `vote` использует fluent-стиль:

```
bitrix_get_orm_entity { "entity": "\\Bitrix\\Vote\\AnswerTable" }
```

**Ожидается**: поля извлечены, у `IMAGE` заполнена связь на `\Bitrix\Main\FileTable`.

## Сценарий 8. События модуля (User Story 3)

```
bitrix_list_events { "module": "sale", "kind": "send" }
```

**Ожидается**: события с именами вида `OnSaleDiscountPresetBuildList`, у каждого — файл, строка и способ вызова.

## Сценарий 9. Параметры компонента с явной неполнотой (User Story 5)

```
bitrix_get_component { "name": "bitrix:main.feedback" }
```

**Ожидается**: параметры `USE_CAPTCHA` (`CHECKBOX`, default `Y`, разрешено), `EMAIL_TO` (`STRING`, `default_resolved: false` — вычисляется в рантайме через настройки модуля), `unresolved_count > 0`.

Ненулевой `unresolved_count` — ожидаемое состояние, следствие запрета на выполнение кода, а не ошибка.

## Сценарий 10. Документация и кириллица (User Story 6)

```bash
php bin/index.php docs
```

**Ожидается**: 112 страниц, разделы framework, get-started, orm, cms-basics, security, database, performance.

```
bitrix_search_docs { "query": "как работать с ORM" }
```

**Ожидается**: релевантные фрагменты из раздела `orm` с рабочими URL.

Повторный запуск `docs` без `--force` не выполняет повторных загрузок неизменившихся страниц (SC-008).

## Сценарий 11. Инкрементальность (User Story 4)

```bash
php -d short_open_tag=1 bin/index.php update
```

**Ожидается** на неизменном ядре: `изменено: 0, добавлено: 0, удалено: 0`, время не более 10% от полной индексации (SC-005).

Затем в копии ядра изменить один файл и удалить другой, повторить: изменения отражены, записи удалённого файла исчезли.

## Сценарий 12. Обнаружение рассинхрона (FR-031)

Подменить `SM_VERSION` в копии ядра и выполнить любой запрос.

**Ожидается**: `provenance.stale = true` и заполненный `stale_reason` — **в ответе обычного инструмента**, а не только в `bitrix_index_status`. Флаг только в диагностике — нарушение: агент, не спросивший о состоянии индекса, получит устаревший факт без предупреждения.

## Сценарий 13. Контрольная выборка

```bash
php bin/index.php verify --fixtures=tests/fixtures/known-symbols.json
```

**Ожидается**: код возврата 0. Выборка проверяет обе стороны — не менее 50 существующих символов находятся с верной версией (SC-001, порог 95%) и не менее 30 заведомо несуществующих не находятся (SC-003, порог 100%).

## Сценарий 14. Переносимость индекса (SC-006)

Скопировать `index.sqlite` в другой каталог, запустить сервер оттуда, выполнить запрос из Сценария 3.

**Ожидается**: работает без переиндексации. Внутри индекса хранятся пути относительно корня ядра, что и делает файл переносимым.
