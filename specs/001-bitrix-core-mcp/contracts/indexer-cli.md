# Contract: CLI индексатора

Индексатор — единственный писатель в файл индекса. Запускается разработчиком вручную после обновления ядра.

## Обязательная преднастройка

**Индексатор MUST отказываться работать при `short_open_tag=Off`.**

```
$ php bin/index.php build
ОШИБКА: short_open_tag выключен.
При этой настройке 27 652 файла ядра (41%) разбираются как HTML без единой ошибки
и молча теряются из индекса. Запустите с явным флагом:
    php -d short_open_tag=1 bin/index.php build
```

Проверка выполняется до открытия БД и до обхода файлов. Это не предупреждение и не деградация — это отказ (R-001).

Штатные точки запуска (`Makefile`, `composer` script) MUST передавать `-d short_open_tag=1` явно, не полагаясь на `php.ini` машины.

## Конфигурация

Приоритет: аргументы CLI → переменные окружения → файл конфигурации → значения по умолчанию. Захардкоженные пути запрещены (FR-014).

| Параметр | Переменная | По умолчанию |
|---|---|---|
| Корень ядра | `BITRIX_CORE_ROOT` | обязателен, без умолчания |
| Путь индекса | `BITRIX_MCP_INDEX` | `./index.sqlite` |
| Дополнительные корни | `BITRIX_EXTRA_ROOTS` | пусто |
| Базовый URL документации | `BITRIX_DOCS_URL` | `https://docs.1c-bitrix.ru` |
| Пауза между запросами, мс | `BITRIX_DOCS_DELAY_MS` | `500` |

Корень ядра не имеет значения по умолчанию намеренно: молчаливое индексирование не того каталога хуже, чем отказ с требованием указать путь.

Дополнительные корни (FR-014) — механизм расширения на кастомный код проекта без переработки. В этой итерации не используются, но структура владения сущностями обязана их допускать.

## Команды

### `build` — полная индексация

```
php -d short_open_tag=1 bin/index.php build [--core=PATH] [--index=PATH] [--no-docs]
```

Создаёт индекс с нуля во временном файле. После успешной проверки целостности новый снимок регистрируется в каталоге версий и атомарно заменяет активный файл; при ошибке активный индекс не меняется.

Порядок: проверка настройки → чтение `SM_VERSION` → чтение карты версий всех модулей → обход файлов → извлечение → запись FTS → сбор документации (если не отключён) → фиксация снимка.

Карта версий читается **до** обхода: без неё ни одна извлечённая сущность не может быть корректно атрибутирована (Принцип II).

**Выход** — сводка в stderr:

```
Ядро:        /path/to/bitrix (SM_VERSION 25.100.300 от 2025-03-21)
Модулей:     99  (без версии: 0)
Файлов:      67836  (212.2 МБ)
Разобрано:   67836  (ошибок: 0)
Символов:    ...    Методов: ...    ORM: ...    Событий: ...
Документация: 112 страниц
Время:       ... с
Индекс:      ./index.sqlite (... МБ)
```

Ненулевое число ошибок разбора MUST печататься с примерами путей и MUST отражаться в `snapshot.parse_error_count`. Доля выше 1% — нарушение SC-009 и повод для расследования, а не для игнорирования.

### `update` — инкрементальная переиндексация

```
php -d short_open_tag=1 bin/index.php update [--docs]
```

Перечитывает карту версий целиком, обходит дерево, сверяя `(размер, mtime)`, при расхождении сверяет SHA-256, перестраивает только изменившееся, удаляет записи исчезнувших файлов (R-010).

Документация по умолчанию НЕ пересобирается — она меняется независимо от ядра и требует сетевых запросов.

**Выход**: `изменено: N, добавлено: M, удалено: K, без изменений: L`.

### `docs` — только сбор документации

```
php bin/index.php docs [--force]
```

Обход по `sitemap.xml` с уважением `robots.txt` и паузой между запросами. Кэш по `ETag` и SHA-256 содержимого; `--force` игнорирует кэш.

Работает через прямые HTTP-запросы — механизм загрузки веб-страниц агента к целевому домену заблокирован сетевой политикой (R-011).

Недоступность сайта MUST завершаться ненулевым кодом возврата, но MUST NOT повреждать уже собранный индекс кода (FR-030, краевой случай спецификации).

### `snapshots` — версии ядра

```
php bin/index.php snapshots [--json]
php bin/index.php snapshot-archive
php bin/index.php snapshot-use --id=SNAPSHOT_ID
php bin/index.php snapshot-delete --id=SNAPSHOT_ID
```

Каждая успешная команда `build`, `update` или `docs` публикует отдельный SQLite-снимок в `<index>.snapshots/` и атомарно заменяет активный индекс. При любой ошибке временный файл удаляется, активный индекс и прежний каталог сохраняются.

`snapshot-archive` регистрирует уже существующий активный индекс без переиндексации. `snapshot-use` активирует архивную версию, сохраняя её в каталоге. `snapshot-delete` удаляет только неактивный снимок; автоматической чистки истории нет.

MCP открывает активный индекс по умолчанию. Конкретную версию выбирают `--snapshot=SNAPSHOT_ID` или `BITRIX_MCP_SNAPSHOT`; `snapshot_id` и `snapshot_role` включаются в provenance каждого ответа.

### `status` — диагностика

```
php bin/index.php status [--deep] [--json]
```

Та же информация, что у MCP-инструмента `bitrix_index_status`, для использования вне агента.

### `verify` — проверка на контрольной выборке

```
php bin/index.php verify --fixtures=tests/fixtures/known-symbols.json
```

Сверка индекса с зафиксированным набором ожиданий: существующие символы находятся с верной версией, заведомо несуществующие — не находятся. Проверка обеих сторон обязательна (раздел «Качество данных и проверка» конституции).

Ненулевой код возврата при расхождении делает команду пригодной для использования как гейт приёмки.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | ошибка конфигурации (нет корня, недоступен путь) |
| 2 | `short_open_tag` выключен |
| 3 | доля ошибок разбора превысила порог |
| 4 | сетевая ошибка при сборе документации |
| 5 | несовместимая версия схемы индекса |

## Инварианты

- Индексатор MUST NOT изменять файлы ядра и MUST открывать их только на чтение (Принцип VI).
- Индексатор MUST NOT подключать загрузчик Битрикса и MUST NOT выполнять код ядра (Принцип VI).
- Индексатор MUST NOT обращаться к базе данных проекта (Принцип VI).
- Повторный `build` на неизменном ядре MUST давать идентичный по содержимому индекс (Принцип V, детерминированность).
- Ошибка разбора одного файла MUST NOT прерывать проход (Принцип V).
