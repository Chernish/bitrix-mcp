# Data Model: Ранжирование полнотекстового поиска

Изменения постоянной схемы нет. Используются существующие `fts_code`, `fts_doc`,
`doc_page` и `module`; версия схемы остаётся 7.

## Поисковый запрос

| Поле | Тип | Правило |
|---|---|---|
| input | string | исходный текст пользователя |
| tokens | string[] | Unicode-буквы/цифры, длина ≥2, без дублей, максимум 12 |
| ftsQuery | string | экранированное соединение токенов через OR |
| limit | integer | 1..10 для кода, 1..5 для документации |

## Внутренний результат ранжирования

| Поле | Тип | Назначение |
|---|---|---|
| rid | integer | стабильный rowid документа |
| matched | integer | число разных совпавших токенов |
| score | real | значение FTS5 bm25, меньше — лучше |

Поля `matched` и `score` внутренние и не расширяют публичный MCP-ответ.

## Переходы

1. Нет допустимых токенов → `found:false`, `reason:"invalid_query"`.
2. Есть токены, но нет строк OR → `found:false`, `reason:"not_in_snapshot"`.
3. Есть строки → сортировка по `matched`, `score`, `rid` и существующий ответ с
   provenance.
